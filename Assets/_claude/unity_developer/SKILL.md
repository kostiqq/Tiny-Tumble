Правила написания кода

1. Управление паматью

Всегда учитывай работу Garbage Collector Unity, при написании кода. Избегай аллокаций.
- **Избегай Boxing'а:** Не передавайте значимые типы (value types) туда, где ожидаются объекты ссылочного типа (например, передача `int` в параметры типа `object` метода `string.Format()`). Это неявно создает в куче временный объект и генерирует мусор.
- **Осторожнее со строками:** Минимизируй их создание в реальном времени и используй класс `StringBuilder` для манипуляций со строками.
- **Правильное использование корутин:** Команда `yield return new WaitForSeconds(1f);` и прочие, которые содержат new, в цикле генерирует новый объект и мусор на каждой итерации. Вместо этого кэшируй объекты в переменные до начала цикла и возвращай именно её.
- **Отказ от замыканий и анонимных методов:** Избегай их в коде, который выполняется каждый кадр. Они выделяют память на куче. 
- **Исключите LINQ и регулярные выражения:** Оба этих инструмента вызывают скрытый боксинг и генерируют мусор. Их следует избегать, по возможности
- **Используйте Non-alloc альтернативы API Unity:** Многие встроенные функции выделяют память. Например, вместо проверки `if (GameObject.tag == "Enemy")` (создающей новую строку) используйте невыделяющую память функцию `GameObject.CompareTag("Enemy")`. Также стоит использовать методы вроде `Physics.RaycastNonAlloc`.
- **Принудительный вызов GC:** Если ты уверен, что игрок не заметит подвисания (например, во время загрузочного экрана), можно вручную запустить очистку кучи вызовом `System.GC.Collect`.
